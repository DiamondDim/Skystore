# Skystore

Учебный проект интернет-магазина плагинов и примеров кода, разработанный в рамках курса Python-разработки Skypro.

## 📌 Описание

Проект представляет собой веб-приложение с каталогом товаров и страницей обратной связи. Особое внимание уделено чистоте кода, правильной архитектуре (паттерн MTV), валидации данных, работе с ORM и эстетике пользовательского интерфейса.

## ✨ Реализованный функционал

### Homework-22: Знакомство с Django

- Настройка проекта Django с использованием менеджера зависимостей **Poetry**.
- Создание и регистрация приложения `catalog`.
- Реализация маршрутизации (URLconf) с правильными окончаниями `/`.
- Создание HTML-шаблонов главной страницы и страницы контактов с использованием **Bootstrap 5**.
- Кастомная стилизация в мягких оливковых тонах (шрифт Montserrat, адаптивные карточки, тени).
- Реализация контроллеров (Views) для обработки GET и POST-запросов.
- Интеграция библиотеки `intl-tel-input` для маски и валидации международных номеров телефонов на клиенте + дублирующая валидация через регулярные выражения на сервере.

### Homework-23: Работа с ORM в Django

- Подключение СУБД **PostgreSQL** с выносом чувствительных данных в `.env`.
- Создание моделей `Category` и `Product` с полями, классом `Meta` и методом `__str__`.
- Связь моделей через `ForeignKey`.
- Настройка административной панели: фильтрация, поиск, кастомное отображение.
- Выполнение ORM-запросов через Django Shell (создание, выборка, фильтрация, обновление, удаление).
- Создание фикстур (`fixtures`) для моделей.
- Реализация кастомной команды `load_test_data` для автоматической загрузки тестовых данных с предварительной очисткой БД.
- Настройка работы с медиафайлами (`MEDIA_URL`, `MEDIA_ROOT`, Pillow).

### Homework-24: Шаблонизация в Django

- **Базовый шаблон `base.html`** с блоками `{% block title %}`, `{% block content %}`, `{% block scripts %}`. Все страницы наследуют его через `{% extends %}`.
- **Подшаблон меню `partials/navbar.html`**, подключаемый во все страницы через `{% include %}`.
- **Детальная страница товара** (`/products/<int:pk>/`, нейминг `product_detail`) с отображением изображения, названия, описания, цены, категории и дат.
- **Каталог товаров** (`/catalog/`) с выводом списка через цикл `{% for %}`, обрезкой описания до 100 символов (`truncatechars:100`) и фильтрацией по категориям.
- **Главная страница как лендинг-визитка** с кнопкой перехода в каталог.
- **Форма добавления товара** (`/add/`) с использованием `ModelForm`, валидацией и сохранением в БД.
- **Умная навигация в футере**: категории «Рассылки» и «Полезные утилиты» ведут на карточки конкретных товаров, остальные категории показывают сообщение «Товаров пока нет. Обратитесь к администратору».
- Двусторонние переходы: главная ↔ каталог ↔ товар.

### Homework-25: Class-Based Views и Блог

- **Перевод всех контроллеров приложения `catalog` с FBV на CBV**: `TemplateView`, `ListView`, `DetailView`, `CreateView`, `FormView`.
- **Создание приложения блога** с моделью `Post` (заголовок, содержимое, превью, дата создания, признак публикации, счётчик просмотров).
- **Реализация полного CRUD для блога через CBV**: `PostListView`, `PostDetailView`, `PostCreateView`, `PostUpdateView`, `PostDeleteView`.
- **Модификации контроллеров**:
  - Фильтрация опубликованных статей (`get_queryset` в `PostListView`)
  - Увеличение счётчика просмотров при открытии статьи (`get_object` в `PostDetailView`)
  - Редирект на страницу статьи после редактирования (`get_success_url` в `PostUpdateView`)
- **Интеграция блога в навигацию и футер**.
- **Написание тестов для блога**.

### Homework-26.1: Формы и валидация данных

- **Реализация CRUD через `django.forms`**: Создана `ProductAddForm` (ModelForm) для создания и редактирования товаров.
- **Кастомная валидация**: 
  - Проверка наличия запрещенных слов (казино, крипта, обман и др.) в полях `name` и `description` с игнорированием регистра.
  - Запрет на указание отрицательной цены через метод `clean_price`.
- **Стилизация форм**: Все поля формы автоматически получают классы Bootstrap (`form-control`, `form-select`, `form-check-input`) через переопределение метода `__init__`.
- **⭐ Дополнительное задание**: Реализована валидация загружаемых изображений в методе `clean_image` (проверка MIME-типа на JPEG/PNG и ограничение размера до 5 МБ).

### Homework-27: Аутентификация в веб-приложениях

- **Кастомная модель пользователя:** Создано приложение users с моделью CustomUser, наследуемой от AbstractUser. Поле email указано как USERNAME_FIELD для авторизации.
- **Дополнительные поля профиля:** Добавлены поля avatar (ImageField), phone_number (CharField) и country (CharField) с соответствующими типами данных.
- **Регистрация пользователей:** Реализована форма CustomUserCreationForm с полями email, username, password1 и password2. Добавлена валидация уникальности username и ограничение на латинские символы через RegexValidator.
- **Приветственное письмо:** После успешной регистрации автоматически отправляется приветственное письмо пользователю через send_mail.
- **Авторизация:** Настроена форма CustomAuthenticationForm для входа по паре email + password с обработкой ошибок валидации.
- **Ограничение доступа:** Использован миксин LoginRequiredMixin для защиты CRUD-операций с продуктами и статьями. Общедоступными остались только страницы просмотра списка товаров и блога.
- **⭐ Дополнительное задание:** Реализован интерфейс редактирования профиля пользователя через ProfileUpdateView с возможностью изменения всех полей модели, включая загрузку аватара.
- **Админка:** Настроена кастомная админка CustomUserAdmin с отображением дополнительных полей и возможностью управления пользователями (создание, редактирование, удаление).
- **UX улучшения:** Создана страница прощания после выхода из системы с кнопками возврата на главную и повторного входа.

### Homework-28: Права доступа и модерация контента (RBAC)
- **Модели**: Добавлены поля `is_published` (BooleanField, default=False) и `owner` (ForeignKey к CustomUser) в модели `Product` и `Post`.
- **Кастомные права**: В модель `Product` добавлено кастомное разрешение `can_unpublish_product` через атрибут `permissions` в классе `Meta`.
- **Автоматизация групп**: Реализована кастомная команда управления `setup_groups`, которая программно создает роли «Модератор продуктов» и «Контент-менеджер» и назначает им соответствующие права (включая стандартные `delete_product`, `change_post` и кастомные).
- **Логика представлений**:
  - При создании контента автор автоматически назначается владельцем (`owner`), а статус жестко устанавливается как "не опубликовано" (`is_published=False`).
  - Внедрен `UserPassesTestMixin` для защиты операций обновления и удаления: доступ разрешен только владельцу объекта или пользователю с соответствующими правами модератора/контент-менеджера.
  - Созданы специализированные представления `PublishProductView` и `PublishPostView`, позволяющие модераторам публиковать контент в один клик прямо из интерфейса, без необходимости заходить в административную панель.
  - Умная фильтрация списков: анонимы видят только опубликованный контент; обычные пользователи видят опубликованный контент + свои собственные черновики; модераторы видят абсолютно все записи для проведения модерации.
- **Шаблоны**: Внедрена условная отрисовка элементов интерфейса. Добавлены визуальные индикаторы статуса ("⏳ На модерации") и динамическое отображение кнопок управления (редактирование, удаление, одобрение) на основе проверки `user == object.owner` или `perms.app_label.codename`.
- **Тестирование**: Написан комплекс модульных тестов (`ProductPermissionsTests`, `BlogPermissionsTests`), проверяющий корректность назначения прав, работу миксинов доступа, защиту от несанкционированных действий (HTTP 403) и корректность workflow публикации.

### Homework-29: Кеширование и сервисный слой (с умной инвалидацией)
- **Интеграция Redis**: Проект настроен на использование `django-redis` для высокопроизводительного хранения данных в оперативной памяти.
- **Сервисный слой (Service Layer)**: Бизнес-логика полностью вынесена из представлений в отдельный модуль `catalog/services.py`. Это обеспечивает соблюдение принципа единственной ответственности (SRP), улучшает читаемость и тестируемость кода.
- **Низкоуровневое кеширование (Low-level Caching)**: 
  - Реализованы функции `get_products_by_category`, `get_all_products` и `get_product_by_id`.
  - Данные кешируются с TTL 15 минут (900 секунд) по ключам `category_{id}`, `all_products_list` и `product_{id}`.
- **Умная инвалидация кеша (Smart Cache Invalidation)**: Реализована функция `invalidate_product_cache`, которая автоматически очищает кеш конкретного продукта, общего списка и связанной категории при любом изменении (`UpdateView`), удалении (`DeleteView`) или модерации (`PublishProductView`) товара. Это гарантирует актуальность данных для пользователей.
- **Оптимизация запросов**: В сервисном слое использован `select_related('category')` для предотвращения проблемы N+1 запросов при рендеринге шаблонов.

## 🔐 Переменные окружения

Создайте файл `.env` в корне проекта на основе `.env.example` и заполните его своими данными:

```env
DB_NAME=skystore_db
DB_USER=postgres
DB_PASSWORD=ваш_пароль
DB_HOST=localhost
DB_PORT=5432
SECRET_KEY=ваш_секретный_ключ
DEBUG=True
```

#### ⚠️ Важно: файл .env не должен попадать в репозиторий — он добавлен в .gitignore.

## 🚀 Установка и запуск

- 1.Клонируйте репозиторий:
```
   git clone <url-репозитория>
   cd Skystore
```
- 2.Установите зависимости через Poetry:
```
   poetry install
```
- 3.Создайте файл .env по образцу .env.example и заполните его.
- 4.Примените миграции для создания структуры БД:
```
      poetry run python manage.py migrate
```
- 5.Создайте суперпользователя для доступа к админке:
```
      poetry run python manage.py createsuperuser
```
- 6.(Опционально) Загрузите тестовые данные с помощью кастомной команды:
```
      poetry run python manage.py load_test_data
```
- 7.Запустите сервер разработки:
```
      poetry run python manage.py runserver
```
- 8.Откройте браузер и перейдите по адресу: http://127.0.0.1:8000/
- Административная панель: http://127.0.0.1:8000/admin/
- Страница контактов: http://127.0.0.1:8000/contacts/
- Каталог товаров: http://127.0.0.1:8000/catalog/
- Добавить товар: http://127.0.0.1:8000/add/
